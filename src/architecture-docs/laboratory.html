What This Context Does

When a doctor orders blood work, an X-ray, or any diagnostic test, the Laboratory context takes over. It tracks the entire lifecycle: the order is created, a specimen is collected (for lab tests), the specimen is processed, results are recorded, and then results are sent back to the requesting clinician.

Results are coded with LOINC codes (Logical Observation Identifiers Names and Codes) — the international standard for lab tests. For example, LOINC code "2345-7" is Glucose in serum/plasma. This standardization enables interoperability between hospitals, reference labs, and public health systems.

In plain English: This is the hospital lab's workflow system. A doctor orders a test, a technician runs it, and the results flow back to the doctor's screen — all tracked, coded, and flagged if something is dangerously abnormal.

Domain Model

LabOrder Aggregate Root

A doctor's request for one or more lab tests. Links to the patient, ordering provider, and the encounter that triggered it.

LabResult Entity

The actual result value with reference ranges. Each test produces one or more results (e.g., CBC produces WBC, RBC, Hemoglobin, Platelets). Flagged as Normal, High, Low, or Critical.

ImagingOrder Entity

X-ray, CT, MRI, or ultrasound orders. Includes body part, contrast requirements, and clinical indication. Results are radiology reports with findings.

Specimen Entity

Physical sample collected from the patient — blood, urine, tissue, swab. Tracked through collection, transport, and processing. Each specimen gets a barcode for chain-of-custody tracking.
