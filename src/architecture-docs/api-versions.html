🔀 Versioning Strategy

The API supports three simultaneous version readers — URL segment (preferred), custom header, and query string. All v1 routes remain backward-compatible at their original paths.

MethodFormatExamplePriority
URL Segment/api/v{N}/resource/api/v2/patientsPreferred
HeaderX-Api-Version: NX-Api-Version: 2Supported
Query String?api-version=N/api/patients?api-version=2Supported
Legacy (v1 only)/api/resource/api/patientsBackward compat
// Program.cs — Multi-version configuration builder.Services.AddApiVersioning(options => { options.DefaultApiVersion = new ApiVersion(1, 0); options.AssumeDefaultVersionWhenUnspecified = true; options.ReportApiVersions = true; options.ApiVersionReader = ApiVersionReader.Combine( new UrlSegmentApiVersionReader(), new HeaderApiVersionReader("X-Api-Version"), new QueryStringApiVersionReader("api-version")); });

🟢 API v1 — Stable Release

The original API with full CRUD operations across 8 domain entities. Entity Framework Core models returned directly. No pagination — returns all matching records. Backward-compatible at both /api/v1/ and legacy /api/ paths.

Endpoints

GET /api/v1/patients

List all patients with optional name search. Returns full entity including navigation property stubs.

?search=lastName

Returns: Patient[]

GET /api/v1/patients/{id}

Get single patient with allergies and last 5 vitals included.

Returns: Patient (with includes)

POST /api/v1/patients

Create new patient. Auto-sets CreatedAt/UpdatedAt timestamps.

Returns: 201 Created + Patient

PUT /api/v1/patients/{id}

Full-entity update. Preserves original CreatedAt timestamp.

Returns: 204 No Content

GET /api/v1/appointments

List appointments with multi-filter support.

?patientId=int?providerId=int?status=string?date=DateTime

Returns: Appointment[] (includes Patient & Provider)

PATCH /api/v1/appointments/{id}/status

Quick status update: Scheduled → Checked-In → In-Progress → Completed / Cancelled.

Returns: 204 No Content

GET /api/v1/prescriptions

Filter prescriptions by patient and status.

?patientId=int?status=Active|Completed|Cancelled

Returns: Prescription[]

GET /api/v1/labresults

Filter lab results by patient and status.

?patientId=int?status=Pending|Completed|Reviewed

Returns: LabResult[]

🔵 API v2 — Enhanced

Production-ready evolution with DTO-based responses, server-side pagination (PagedResult), clinical dashboard, patient summary endpoints, provider workload metrics, and advanced sorting/filtering. No raw EF entities leak through — all responses use purpose-built DTOs.

Key Improvements over v1

📄 Pagination

Every list endpoint returns PagedResult<T> with items, totalCount, page, pageSize, totalPages, hasNextPage, hasPreviousPage. Max 100 items per page.

🎯 DTO Responses

Dedicated record DTOs for list views vs. detail views. No EF entity cycles, no over-fetching. PatientListDto has allergy count and active Rx count as computed fields.

📊 Clinical Dashboard

New /api/v2/dashboard — real-time KPIs: total patients, active providers, today's appointments, pending labs, active prescriptions, critical alerts.

🩺 Clinical Summary

/api/v2/patients/{id}/clinical-summary — single endpoint returning complete patient context: demographics, allergies, vitals, appointments, records, prescriptions, labs.

📅 Provider Schedule

/api/v2/providers/{id}/schedule — date-range filtered appointment list. ProviderDetailDto includes workload metrics: today/week/month appointment counts.

🔍 Advanced Filters

Multi-column sort (sortBy, sortDir), gender filter, medication name search, encounter type filter, diagnosis code search, date range for appointments.

Endpoints

GET /api/v2/patients

Paginated patient list with search across name, email, and insurance ID. Sortable by lastName, firstName, dob, or createdAt.

?search?gender?sortBy=lastName?sortDir=asc|desc?page=1?pageSize=20

Returns: PagedResult<PatientListDto>

GET /api/v2/patients/{id}

Detailed patient with allergies, recent vitals, and computed stats (total appointments, records, active prescriptions, pending labs, last visit date).

Returns: PatientDetailDto (includes PatientStatsDto)

GET /api/v2/patients/{id}/clinical-summary

Complete clinical summary — patient detail + last 10 appointments + last 10 records + active prescriptions + pending labs. Single call for full patient context.

Returns: PatientClinicalSummary

GET /api/v2/dashboard

Clinical dashboard KPIs with upcoming appointments and critical lab alerts.

Returns: ClinicalDashboardDto (6 KPIs + 2 lists)

GET /api/v2/providers/{id}/schedule

Provider's appointment schedule for a date range.

?from=DateTime?to=DateTime

Returns: AppointmentListDto[]

GET /api/v2/appointments/today

Today's appointments across all providers, sorted by scheduled time.

Returns: AppointmentListDto[]

GET /api/v2/prescriptions

Paginated prescriptions with patient, status, and medication name filters.

?patientId?status?medication?page?pageSize

Returns: PagedResult<PrescriptionDto>

GET /api/v2/labresults

Paginated lab results with patient, status, flag, and test name filters.

?patientId?status?flag=Critical|High|Low?testName

Returns: PagedResult<LabResultDto>

🟣 API v3 — Future Preview

Next-generation capabilities including HL7 FHIR R4 interoperability, AI-powered clinical decision support, predictive analytics, bulk export, and real-time event streaming. Returns simulated responses for demonstration — full implementation planned for Phase 3.

Future Capabilities

🏥 FHIR R4 Patient

HL7 FHIR-compliant Patient resource with Bundle search responses. Maps EHR patients to StructureDefinition/us-core-patient.

  • Search by family, given, gender
  • FHIR Bundle searchset response
  • Identifier system for insurance
  • US Core profile compliance

🤖 AI Decision Support

Drug interaction checking, clinical guideline recommendations, and evidence-based care alerts powered by ML models.

  • Drug-drug interaction detection
  • Severity scoring (Mild/Moderate/Severe)
  • Clinical guideline matching
  • Always includes safety disclaimer

📈 Predictive Analytics

Readmission risk scoring based on patient history, population health insights with trend analysis.

  • 30-day readmission risk score
  • Contributing factor identification
  • Population health metrics
  • Trend analysis with change %

📡 Real-time Streaming

Webhook-based event subscriptions for clinical events. Subscribe to patient, lab, vitals, and prescription events.

  • 12 event types across 6 categories
  • Webhook subscription management
  • Active subscription monitoring
  • Event type catalog endpoint

📦 Bulk FHIR Export

Async bulk export jobs following FHIR Bulk Data specification. Export Patient, Observation, and MedicationRequest resources as NDJSON.

  • Async job with status polling
  • NDJSON output format
  • Resource type selection
  • Since-date filtering

🔮 GraphQL Gateway

Planned — Single query endpoint for complex data requirements. Reduce over-fetching with field-level selection.

  • Field-level data selection
  • Nested relationship traversal
  • Subscription for real-time updates
  • Schema introspection

Endpoints

GET /api/v3/fhir/Patient

FHIR R4 Patient search — returns a Bundle searchset with US Core profile compliance.

?family?given?gender?_count=20?_offset=0

Returns: FhirBundle

GET /api/v3/fhir/Patient/{id}

Read single patient as FHIR Patient resource with meta, identifiers, and telecom.

Returns: FhirPatientResource

POST /api/v3/ai/drug-interactions

Check for drug-drug interactions. Provide active diagnoses and current medications list.

Returns: ClinicalDecisionResponse (interactions + guidelines)

POST /api/v3/ai/guidelines

Get evidence-based clinical guideline recommendations for diagnoses.

Returns: ClinicalDecisionResponse (guidelines + actions)

GET /api/v3/ai/readmission-risk/{patientId}

Predict 30-day readmission risk based on patient history and clinical data.

Returns: ReadmissionRiskResponse (score + factors)

GET /api/v3/ai/population-health

Population-level health insights and trend metrics across the patient census.

Returns: PopulationHealthInsight[]

POST /api/v3/bulk/export

Start an async bulk FHIR export job. Select resource types and date filter.

Returns: 202 Accepted + BulkExportStatus

GET /api/v3/streaming/event-types

Catalog of all available streaming event types across 6 clinical categories.

Returns: 12 event types with descriptions
